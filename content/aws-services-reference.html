AWS services in the YourStoriesLive setup

Developer reference · Current development/SIT infrastructure · Based on the BFF and frontend infrastructure definitions

This describes the services configured for the current AWS design. It does not mean every resource is always running: ECS tasks and RDS can be paused for cost savings.

How a request and deployment flow

Developer push
  └─ GitHub Actions → GitHub OIDC / AWS STS → IAM deployment role
       ├─ builds image → Amazon ECR
       └─ deploys → CloudFormation (templates authored with CDK)

Browser → HTTPS → CloudFront
                 ├─ frontend + Next assets → public ALB :8080 → ECS/Fargate frontend :3000
                 └─ /api/* →─────────────── public ALB :80   → ECS/Fargate BFF :3001
                                                               ├─ private RDS PostgreSQL
                                                               ├─ private S3 media bucket
                                                               └─ SQS processing queue → DLQ

CloudFront provides browser-facing HTTPS on its generated hostname. It forwards to the shared ALB over HTTP in the current development configuration. The ALB spans two Availability Zones; RDS is isolated in private subnets. ECS tasks currently use public subnets/public IP assignment. The frontend task's security group only accepts its app port from the ALB security group.

Services used

AWS serviceWhy it is hereHow this application uses it
Amazon CloudFrontGlobal edge entry point, HTTPS for the generated hostname, and delivery/caching for frontend assets.Default behavior and /_next/static/* go to the frontend ALB listener on port 8080. /api/* goes to the BFF listener on port 80. Price Class 200 is configured for broad Asia-Pacific coverage.
Elastic Load Balancing — ALBStable public origin, Layer-7 routing, and health-based forwarding to application targets.One shared ALB serves BFF on port 80 and frontend on port 8080, through separate target groups/health checks. CloudFront forwards to those listeners.
Amazon ECSSchedules and maintains containerized services.BFF runs in ysl-bff-dev-cluster; the Next.js service shares that cluster. Desired count can be zero while paused.
AWS FargateRuns containers without managing EC2 hosts.BFF task: 0.25 vCPU / 512 MiB. Frontend task: 1 vCPU / 2 GiB. Both register behind the ALB.
Amazon ECRPrivate container-image registry.Separate BFF/frontend repositories store deployable images. Image scanning on push and a latest-images lifecycle policy are configured; ECS pulls the selected image.
Amazon RDS for PostgreSQLRelational persistence for new application-owned records, separate from the legacy PHP database.BFF connects privately to PostgreSQL in isolated subnets. Current dev configuration: PostgreSQL 16, db.t4g.micro, 20 GiB gp3, autoscaling to 100 GiB, encrypted, Single-AZ, one-day automated backup retention.
Amazon S3Stores media bytes without putting large files in PostgreSQL or app containers.Private bucket, public access blocked, SSL enforced, S3-managed encryption, browser CORS for signed PUT/GET, and cleanup of incomplete multipart uploads. BFF authorizes ownership and issues short-lived presigned URLs.
Amazon SQSDurable buffer for asynchronous work.Media-processing queue and dead-letter queue are provisioned; BFF task permissions are present. A queue does not process jobs on its own—a worker must consume them.
AWS Secrets ManagerKeeps credentials out of source and container images.Stores generated RDS credentials, JWT, legacy API client, and social-import secrets. ECS injects selected values into the BFF task at startup.
AWS IAMDefines AWS identities and permissions.GitHub deployment, ECS task, and ECS execution roles have separate permissions for deploy, image pull, logs, S3/SQS, and secret access.
AWS STS + IAM OIDC providerFederates GitHub Actions and issues short-lived credentials.GitHub Actions presents an OIDC token; STS allows a restricted IAM deployment role to be assumed. No long-lived AWS key is needed in GitHub.
Amazon CloudWatchLogs, metrics, and alarms.Frontend/BFF container logs use seven-day log groups; PostgreSQL logs are exported. BFF CPU and unhealthy-target alarms are defined; Container Insights is enabled for the BFF cluster.
Amazon VPCNetwork isolation, subnetting, routing, and security groups.Two AZs; public application subnets and isolated private database subnets; zero NAT Gateways. RDS has no public endpoint and permits PostgreSQL from the BFF service.
Public IPv4 / Internet GatewayInternet connectivity for the public ALB and the present public-subnet task design.ALB has public addresses across enabled AZs. Each Fargate task configured with public-IP assignment can also receive an address. Task addresses are ephemeral; no NAT Gateway is provisioned.
AWS KMS (AWS-managed keys)Key management underlying encrypted storage.RDS storage encryption and AWS-managed S3/SQS encryption are enabled. No customer-managed KMS key is explicitly configured.
AWS Systems Manager message channelsSecure operator access for ECS Exec troubleshooting.ECS Exec is enabled on BFF; the task role has ssmmessages permissions. This is not part of normal application request handling.
AWS CloudFormationTracks and applies infrastructure as managed stacks.CDK-generated BFF and frontend templates create/update resources. A code-only deployment is intended to update the task definition/service rather than replace persistent data or networking.

Tools and concepts, not standalone AWS services here

  • AWS CDK is the infrastructure-as-code toolkit; it synthesizes CloudFormation templates.
  • GitHub Actions is the external CI/CD runner. It tests/builds images and uses OIDC to request temporary AWS credentials.
  • OIDC is the federation protocol; AWS trust is configured in IAM and STS issues temporary credentials.
  • Next.js and NestJS are application frameworks running in ECS containers.

Not currently in the deployed path

  • Route 53 and ACM: optional custom DNS/certificate settings exist in the BFF CDK, but the current setup uses CloudFront's generated hostname and HTTP from CloudFront to ALB. No custom DNS record or ALB certificate is required for that hostname.
  • Lambda, API Gateway, NAT Gateway, WAF, SNS, and a media worker: not part of the current request path/configuration. SQS is provisioned, but a worker is still needed for queued processing.
  • Legacy PHP database connection: none. The new RDS instance is standalone. BFF calls to legacy PHP APIs are HTTP integration, not shared database access.

For normal traffic: CloudFront → ALB → ECS/Fargate. The BFF uses RDS for metadata and S3 for bytes; SQS/DLQ support asynchronous processing. IAM, Secrets Manager, VPC, and CloudWatch provide permissions, secret delivery, isolation, and visibility. ECR plus GitHub Actions/OIDC/STS and CloudFormation/CDK form the deployment path.

This inventory reflects infrastructure definitions, not a live account audit. Check the AWS console/CLI for current deployed, running, or paused state before operational or cost decisions.
